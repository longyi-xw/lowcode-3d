# v0.2 材质编辑 sub-stage 设计

**状态**: 已批准（2026-06-03）
**前置**: v0.2 资源库 sub-stage（PR #29）已合并到 main。
**定位**: v0.2 的第二个、也是最后一个 sub-stage。完成后 v0.2 收尾。

---

## 1. 目标

让用户在属性面板编辑 mesh 节点的 PBR 材质参数，编辑可撤销/重做，导出代码（Vite + Standalone）包含正确的材质字段。

## 2. Success criteria

1. 属性面板能编辑选中 mesh 节点的 6 个材质参数（baseColor / metalness / roughness / emissive / emissive_intensity / opacity），改动**实时**反映在视口。
2. 每次编辑走 Command，undo/redo 有效；连续拖动滑块合并为**单条** undo 记录。
3. 导出代码（两个目标）emit 的 `MeshStandardMaterial` 含正确字段；`opacity < 1` 时带 `transparent: true`。
4. `pnpm lint && pnpm typecheck && pnpm test` 全绿 + `pnpm tauri dev` 人工视觉验证通过。

## 3. 范围

### In scope

- 单材质槽（`material_overrides[0]`，slot 0）的 6 个标量/颜色参数。
- `src/core/scene/material.ts`：`DEFAULT_MESH_MATERIAL` + `resolveMaterial(override?)` 纯函数（默认 ⊕ override → 有效值），面板 / runtime / codegen 三处共用。
- `SetMaterialOverrideCommand` + `useSceneStore.setMeshMaterial` mutator。
- 属性面板 `MaterialSection`（仅 mesh 显示）+ `SliderRow` 控件。
- `emitMesh` 读 override 后 emit 材质字段。

### Out of scope（延后 backlog — 显式记录，避免遗忘 / 后期幻觉）

> 同步回填到 `docs/roadmap.md` 的 Backlog 区。

1. **材质贴图 pipeline**（normalMap / map / roughnessMap / metalnessMap / aoMap 等）。需要：
   - `MaterialOverrideSchema` 加贴图字段（如 `normal_map_asset_id?: string` 等，引用 texture 类 `AssetReference`）。
   - texture 类资源上传入库（把 `uploadGlbToLibrary` 思路扩展到图片：`kind: "texture"` 的 `AssetReference`）。
   - runtime：`mesh.ts` 的 `applyOverrides` 增加贴图通道（`THREE.TextureLoader` 加载，按 assetId 解析到 `assets/` 路径）。
   - codegen：`emitMesh` emit `new THREE.TextureLoader().load("./assets/…")` 并挂到 material 对应通道。
   - UI：材质面板的贴图选择器（从库里的 texture 资源选）。
   - 是独立子系统，单独 spec → plan → 实现。
2. **资源拖拽入视口 + 落点**。当前资源库为**双击**加节点到默认位置（几何抬 `y=0.5`）。延后：从库卡片**拖拽**到视口，以 raycast 命中地面/物体的点作为新节点 `position`。
3. **多源资源上传**。`AssetSourceSchema` 已是来源无关（`builtin` / `user_upload` / `online` / `ai_generated`），catalog 也来源无关；目前只实装 `builtin`（几何/灯光预设）+ `user_upload`（.glb）。延后：`online`（在线模型/材质库浏览 + 下载入库）、`ai_generated`（AI 生成模型/贴图）。
4. **多材质槽**（slot 1+，针对 prefab/glTF 多材质对象）。本期只 slot 0。

## 4. 数据模型

复用现有 schema（`src/core/scene/schemas.ts`，**不改**）：

```ts
// 已存在
const MaterialOverrideSchema = z.object({
  slot: z.number().int().nonnegative(),
  color: ColorHexSchema.optional(),
  metalness: z.number().min(0).max(1).optional(),
  roughness: z.number().min(0).max(1).optional(),
  opacity: z.number().min(0).max(1).optional(),
  emissive: ColorHexSchema.optional(),
  emissive_intensity: z.number().nonnegative().optional(),
});
// mesh 变体已有: material_overrides: z.array(MaterialOverrideSchema).optional()
```

新增 `src/core/scene/material.ts`（单一默认来源 + 解析纯函数）：

```ts
import type { NodeData } from "./types";

type MaterialOverride = NonNullable<
  Extract<NodeData, { type: "mesh" }>["material_overrides"]
>[number];

export interface ResolvedMaterial {
  color: string; // hex #rrggbb
  metalness: number;
  roughness: number;
  emissive: string; // hex #rrggbb
  emissive_intensity: number;
  opacity: number;
}

/** Single source of truth for a mesh's default material — previously hard-coded
 *  in mesh.ts (builder) and emitMesh (codegen). */
export const DEFAULT_MESH_MATERIAL: ResolvedMaterial = {
  color: "#cccccc",
  metalness: 0,
  roughness: 0.7,
  emissive: "#000000",
  emissive_intensity: 1,
  opacity: 1,
};

/** Default ⊕ override → fully-resolved material. Used by the panel (display),
 *  the runtime builder (render), and codegen (export) so all three agree. */
export function resolveMaterial(override?: MaterialOverride): ResolvedMaterial {
  return {
    color: override?.color ?? DEFAULT_MESH_MATERIAL.color,
    metalness: override?.metalness ?? DEFAULT_MESH_MATERIAL.metalness,
    roughness: override?.roughness ?? DEFAULT_MESH_MATERIAL.roughness,
    emissive: override?.emissive ?? DEFAULT_MESH_MATERIAL.emissive,
    emissive_intensity:
      override?.emissive_intensity ?? DEFAULT_MESH_MATERIAL.emissive_intensity,
    opacity: override?.opacity ?? DEFAULT_MESH_MATERIAL.opacity,
  };
}
```

> 注：UI 的 “Base Color” 对应 schema 字段 `color`；“Emissive” 对应 `emissive`。

## 5. 架构 / 组件（每单元职责 + 数据流）

### 5.1 Command — `SetMaterialOverrideCommand`

`src/core/command/commands/set-material-override.ts`，镜像 `SetNodeTransformCommand`：

```ts
export const SET_MATERIAL_OVERRIDE = "node.material.set" as const;
export const MERGE_WINDOW_MS = 500;

interface SetMaterialOverridePayload extends Record<string, unknown> {
  node_id: string;
  override: MaterialOverride | undefined;
  prev_override: MaterialOverride | undefined;
}
// apply  → store.setMeshMaterial(node_id, override)
// revert → store.setMeshMaterial(node_id, prev_override)   // undefined = 清空
// canMergeWith: 同 type + 同 node_id + |Δtimestamp| < 500ms
// mergeWith: 取 earliest prev_override + latest override，复用 this.id
```

### 5.2 Store mutator — `setMeshMaterial`

`useSceneStore`（`src/services/scene/store.ts`）+ 命令窄接口 `SceneEditorStore`（`src/core/command/types.ts`）+ `getSceneEditorStore` 适配 + `_test-utils` 的 `FakeEditor`：

```ts
setMeshMaterial(nodeId: string, override: MaterialOverride | undefined): void
```

实现模式同 `setBehaviorParameters`：取 node，若 `node.data.type !== "mesh"` 则 no-op；构造
`nextData = { ...node.data, material_overrides: override ? [override] : undefined }`；`mutateNode(s, nodeId, { ...node, data: nextData })`。

### 5.3 面板 — `MaterialSection`

`src/ui/editor/MaterialSection.tsx`，在 `EditorView` 的 `NodeProperties` 内、仅当 `node.data.type === "mesh"` 渲染。

- 读 `const m = resolveMaterial(node.data.material_overrides?.[0])` 作为各控件显示值。
- 编辑某字段 `field` 为 `value` 时：
  ```ts
  const cur = node.data.material_overrides?.[0];
  const next = { slot: 0, ...cur, [field]: value };
  executeCommand(
    new SetMaterialOverrideCommand({
      node_id: node.id,
      override: next,
      prev_override: cur,
    }),
  );
  ```
- 选中保持不变（编辑材质不改选中）。

### 5.4 Runtime — `mesh.ts`

`applyOverrides` 已实现按 override 改 material。仅把 build/update 里写死的 `{ color: 0xcccccc, metalness: 0, roughness: 0.7 }` 改为基于 `DEFAULT_MESH_MATERIAL`（或直接用 `resolveMaterial` 设初值），保证与面板/codegen 默认一致。其余不动（build/update 已读 `material_overrides?.[0]`）。

### 5.5 Codegen — `emitMesh`

`src/runtime/three/export/scene-codegen.ts`：

```ts
const m = resolveMaterial(node.data.material_overrides?.[0]);
push(
  ctx,
  `const ${v}_mat = new THREE.MeshStandardMaterial({ ` +
    `color: ${JSON.stringify(m.color)}, metalness: ${m.metalness}, roughness: ${m.roughness}, ` +
    `emissive: ${JSON.stringify(m.emissive)}, emissiveIntensity: ${m.emissive_intensity}, ` +
    `opacity: ${m.opacity}, transparent: ${m.opacity < 1} });`,
);
```

无 override 时 = 现状默认（仅颜色从 `0xcccccc` 改为等价的 `"#cccccc"` 字符串，THREE 接受 CSS 颜色串）。仍满足 “no-TS-syntax” 断言（无 `: THREE.`）。

## 6. 控件

- 颜色（baseColor / emissive）：`<input type="color">`（`HoverHighlightForm` 先例），值为 hex。
- 0-1 标量（metalness / roughness / opacity）+ emissive_intensity（≥0，step 0.1，软上限如 4）：新增 `src/ui/editor/SliderRow.tsx` — 原生 `<input type="range">` + 数值框（数值框可精确输入，二者同步；onChange 即时 dispatch，连续值经 command merge 合一）。`disabled` 接 locked / play。

## 7. 边界 / 错误处理

- 仅 mesh 节点显示材质区（group / light / camera / prefab_instance / helper 不显示）。
- locked 节点 / play 模式：控件 `disabled`（沿用 `NodeProperties` 外层 `fieldset disabled` 即自动覆盖）。
- 不做 “override 全等于默认就删除 override” 的优化（避免编辑过程抖动；YAGNI）。
- 数值越界：range 天然 clamp 0-1；数值框 onBlur 校验非有限值回退（参考 `NumberInput`）。

## 8. 测试策略（TDD，每单元红-绿）

- `material.test.ts`：`resolveMaterial(undefined)` = 默认；`resolveMaterial(部分 override)` 仅覆盖给定字段。
- `set-material-override.test.ts`：apply/revert（含 prev=undefined 清空）、canMergeWith（同节点窗口内）、mergeWith（earliest prev + latest override）、never-merge 跨节点/超窗。
- store `setMeshMaterial` test：写 mesh override / 非 mesh no-op / undefined 清空。
- `scene-codegen.test.ts`：mesh 带 override → emit 含对应字段 + `transparent: true`（opacity<1）；无 override → 默认；“no-TS-syntax” 回归仍绿。
- `MaterialSection.test.tsx`：编辑滑块/颜色 → dispatch `SetMaterialOverrideCommand`（仿 `LibraryPanel.test`）。
- 人工 `pnpm tauri dev`：改 baseColor/metalness/roughness/emissive/opacity 视口实时变；undo/redo（含拖动合并）；导出 Vite + Standalone 运行后材质正确。
