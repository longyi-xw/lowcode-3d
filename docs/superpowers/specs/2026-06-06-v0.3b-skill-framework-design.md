## 1. 目标

自然语言指令 → LLM 结构化输出 → 映射为可撤销的 Command。首个 skill `scene-edit` 实现「加灯」：用户在命令栏输入「添加一盏从右上方照射的暖白色定向光」，场景里真的出现对应 DirectionalLight 节点（可 Cmd+Z 撤销）。用 DeepSeek（sub-stage A 的 active provider）测真实调用。

## 2. Success criteria

1. 编辑器常驻 AI 命令栏，输入自然语言 → 回车 → 调 LLM（active provider，DeepSeek）→ 结构化输出 → 加灯。
2. 加的灯走 `AddNodeCommand`（executeCommand），**Cmd+Z 撤销 / Cmd+Shift+Z 恢复**有效。
3. 错误有明确反馈：无 key / 网络 / API 错（`AiError`）、LLM 输出无法解析/校验、无改动 → 各自 toast。
4. `docs/skill-guide.md` 从 TBD 填为本期 MVP 的真实接口文档。
5. `pnpm lint && pnpm typecheck && pnpm test` 全绿 + `pnpm tauri dev` 人工验证（用户 DeepSeek key）。

## 4. 数据模型 / 类型（`src/services/skills/types.ts`）

```ts
import type { Command } from "@/core/command/types";

/** 本期唯一 op。position：灯的世界坐标（方向光从此处朝原点照）。 */
export interface AddLightOperation {
  op: "add_light";
  light_kind: "directional" | "point" | "spot" | "ambient";
  color: string; // hex #rrggbb
  intensity: number;
  position: [number, number, number];
  cast_shadow?: boolean;
}
export type Operation = AddLightOperation;

/** 精简自架构 §4.3。省略 memory/call_tool（单轮模型不需要）；allowed_tools/
 *  examples 作可选元数据。execute 由共享 runner 跑（见 run.ts）。 */
export interface Skill {
  id: string;
  name: string;
  systemPrompt: string;
  /** 发给 LLM 的 JSON Schema（aiComplete 的 jsonSchema）。 */
  outputSchema: Record<string, unknown>;
  /** zod 校验 LLM 返回的 JSON → operations（非法抛错）。 */
  parse(json: unknown): Operation[];
  /** operations → 可撤销 Command。 */
  buildCommands(ops: Operation[]): Command[];
}

export interface SkillResult {
  count: number; // 执行的 Command 数
}

/** skill 侧失败（区别于 proxy 的 AiError）：LLM 没产出结构化 / 无法解析。 */
export class SkillError extends Error {
  constructor(public code: "no_output" | "parse") {
    super(code);
    this.name = "SkillError";
  }
}
```

## 5. 架构 / 组件（职责 + 数据流）

### 5.1 执行循环 `runSkill(skillId, input)`（`run.ts`）

```ts
export async function runSkill(skillId: string, input: string): Promise<SkillResult> {
  const skill = SKILLS[skillId];
  if (!skill) throw new Error(`unknown skill: ${skillId}`);
  const res = await aiComplete({
    system: skill.systemPrompt,
    user: input,
    jsonSchema: skill.outputSchema,
  });
  if (!res.json) throw new SkillError("no_output");
  let raw: unknown;
  try {
    raw = JSON.parse(res.json);
  } catch {
    throw new SkillError("parse");
  }
  let ops: Operation[];
  try {
    ops = skill.parse(raw); // zod
  } catch {
    throw new SkillError("parse");
  }
  const cmds = skill.buildCommands(ops);
  for (const cmd of cmds) executeCommand(cmd);
  return { count: cmds.length };
}
```

- `aiComplete` 抛 `AiError`（no_key/network/api）→ 向上传给命令栏。
- 每 `executeCommand` 一条 undo（本期）。

### 5.2 `scene-edit` skill（`scene-edit.ts`）

- `systemPrompt`：3D 场景助手；Y-up；方向光从其 `position` 朝原点照；约定「右上」≈`[5,6,4]`、「暖白」≈`#ffe8c0`、「冷白」≈`#dfe8ff`；只输出 `add_light` operations；用结构化输出。含 1 个 few-shot 示例（"a warm white directional light from the upper right" → `{operations:[{op:"add_light",light_kind:"directional",color:"#ffe8c0",intensity:1.2,position:[5,6,4],cast_shadow:true}]}`）。
- `outputSchema`（JSON Schema，发给 LLM）：`{ type:"object", properties:{ operations:{ type:"array", items:{ ...add_light 字段, required:[op,light_kind,color,intensity,position] } } }, required:["operations"] }`。
- `parse`：zod
  ```ts
  const AddLightOpSchema = z.object({
    op: z.literal("add_light"),
    light_kind: z.enum(["directional", "point", "spot", "ambient"]),
    color: z.string().regex(/^#[0-9a-fA-F]{6}$/),
    intensity: z.number().nonnegative(),
    position: z.tuple([z.number(), z.number(), z.number()]),
    cast_shadow: z.boolean().optional(),
  });
  const OperationsSchema = z.object({ operations: z.array(AddLightOpSchema) });
  parse: (json) => OperationsSchema.parse(json).operations;
  ```
  > color 用 hex 正则严格校验（systemPrompt + few-shot 都给 hex）；非法 → 抛 → toast「未能理解」。
- `buildCommands`：`ops.map(op => new AddNodeCommand({ node: buildLightNode(op) }))`。
- `buildLightNode(op)`：`{ id: generateUUID(), name: lightName(op.light_kind), type:"light", transform:{position:op.position, rotation:[0,0,0,1], scale:[1,1,1]}, parent_id:null, children_ids:[], visible:true, locked:false, data:{type:"light", light_kind:op.light_kind, color:op.color, intensity:op.intensity, ...(op.cast_shadow!==undefined?{cast_shadow:op.cast_shadow}:{})}, behaviors:[], user_data:{} }`（复用现有 light SceneNode 形状）。`lightName` 由 light_kind 映射（如 "Directional Light"）。

### 5.4 UI — `AiCommandBar`（`src/ui/editor/`）

中间列 flex-col 顶部 slim bar：`Sparkles` 图标 + 输入框（placeholder `ai_command.placeholder`）+ 发送按钮（回车提交）+ busy 态（thinking）。提交：

成功 → `toast.success(t("ai_command.done", { count }))`（count=0 → `ai_command.no_changes`）；`SkillError` → `toast.error(t("ai_command.didnt_understand"))`；`AiError` → `toast.error(t("ai_command.llm_error", { message }))`。play 模式禁用输入。挂在 EditorView 中列 viewport **上方**（slim row，不覆盖视口）。

## 6. 错误处理

- proxy `AiError`（no_key→「未配置 API key」/ network / api_error{status,message}）→ `ai_command.llm_error`。
- `SkillError`（no_output/parse）+ zod 校验失败 → `ai_command.didnt_understand`。
- 空 operations（count=0）→ `ai_command.no_changes`。
- 沿用 3.3 toast（成功自消 / 错误持久）。

- **真实 LLM 调用进不了 CI**：runSkill/scene-edit/bar 用 mock proxy 单测；真实链路靠人工（DeepSeek）。
- 延后项（§3）：agentic 多轮、MemoryStore、其它 skill、skill routing、多 op 单 undo、自动选中——记 roadmap Backlog。
