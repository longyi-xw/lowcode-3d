# Phase 3 · 3.3 错误处理 polish 设计

> 状态：设计已获用户批准（2026-06-01）。下一步 writing-plans。
> 决议：v0.1.0 **含** 3.3，做完它再做 3.5 发版（3.5 暂停）。本 sub-stage 在 `feat/phase3-3.3-errors` 分支。

## 1. 目标 / 成功标准

给 v0.1 补上三层错误网，让任何失败都「被看见」而不是白屏/静默。

成功标准：

1. ✅ React 渲染崩溃被全局 ErrorBoundary 捕获 → 显示 CrashFallback（不白屏）。
2. ✅ IO 操作（save/open/import/export）成功有自动消失 toast、失败有持久 error toast。
3. ✅ `window` 'error' / 'unhandledrejection' 全局兜底 → console.error + error toast（非致命）。
4. ✅ 交互式确认（confirmDiscard / overwrite / save-first）仍走原生 `ask()` 不变。
5. ✅ lint / typecheck / test 全绿；视觉验证清单（§11）通过。

## 2. 背景 / 现状

- **无 toast 库**：`src/components/ui/` 只有 button/dialog/dropdown-menu/tabs/tooltip。`package.json` 无 sonner/toast。
- **无 ErrorBoundary**：全仓搜不到 `componentDidCatch`/`getDerivedStateFromError` → 任何渲染报错白屏。
- **无全局兜底**：搜不到 `window.addEventListener("error"/"unhandledrejection")`。
- **IO 错误现状**（`src/services/project/actions.ts`）：`reportError(e)` → `reportRawError(msg)` → Tauri `ask()` 阻塞原生框；非 Tauri 走 `console.error`。成功无任何提示。
- **交互式确认**：`confirmDiscard(msg)`（`actions.ts:426`，非 dirty 早返 true；非 Tauri 用 `window.confirm`；Tauri 用 `ask`）、overwrite-ask、save-first —— 这些是**确认**不是错误通知，保留。
- **现有 `ErrorView`**（四视图之一 startup/loading/editor/error）是**项目加载失败页 mockup**（写死 schema-mismatch 示例 + 假路径 + Try again / migration 按钮），仅被 StartupView 的 clone-from-URL `open("error")` 当模拟触发。**语义 = 项目加载错误，不是应用崩溃**，本 sub-stage 不动它。
- **`main.tsx`**：`createRoot(...).render(<StrictMode><App/></StrictMode>)`，import `./i18n` / css / `./ui/dev/dev-tools`（模块副作用注册 dev helpers 的先例）。
- **i18n**：已有 `errors` namespace（`errors.json` 含 `project_load.*` / `back_to_startup`）。主题在 `useSettingsStore.theme`（light/dark/system）。
- **App.tsx 根**：已挂 `<NewProjectDialog />`（3.2），是挂 `<Toaster/>` 的对应位置。

## 4. sonner toast 基建

- `pnpm add sonner`。
- `App.tsx`：`<Toaster richColors position="bottom-right" theme={theme} />`，`theme` 来自 `useSettingsStore((s) => s.theme)`（值 light/dark/system 与 sonner 的 theme prop 一致）。挂在与 `<NewProjectDialog/>` 平级处。
- 业务代码 `import { toast } from "sonner"` 直接调，不需 hook（全局 handler / actions 等非组件上下文也能用）。

## 5. IO toast 路由（`src/services/project/actions.ts`）

- **成功 toast**（`toast.success`，默认自动消失）加在各 action 的成功分支：
  - `saveProject` 成功（写盘 ok）→ "已保存 / Saved"
  - `openProject` 成功（load ok）→ "已打开 {name} / Opened {name}"
  - `importGlb` 成功 → "已导入 {filename} / Imported {filename}"
  - `exportProject` 成功 → "已导出到 {path} / Exported to {path}"
  - **不放在 `loadProjectIntoEditor`**（它被 New-from-template 复用，会误报「opened」）；放在各 action 函数体。New-from-template 不发 toast（编辑器已可见变化，且非 IO）。
- **错误 toast**：`reportError(e)` / `reportRawError(msg)` 体内 `ask()` 调用改为 `toast.error(msg, { duration: Infinity })`（持久，手动关）。两函数签名保持（`Promise<void>`）不动调用方；body 不再 `await ask`。
- **保留 `ask()`**：`confirmDiscard`、overwrite 确认、save-first 提示原样不动。

## 6. ErrorBoundary + CrashFallback

- `src/ui/error/ErrorBoundary.tsx`：class 组件。
  - `state = { error: Error | null }`；`static getDerivedStateFromError(error)` → `{ error }`；`componentDidCatch(error, info)` → `console.error("[ErrorBoundary]", error, info)`。
  - `render()`：有 error 渲染 `<CrashFallback error={this.state.error} />`，否则 `this.props.children`。
  - props：`{ children: ReactNode }`。
- `src/ui/error/CrashFallback.tsx`：`{ error: Error | null }`。
  - 居中卡片（复用 ErrorView 的 `h-screen w-screen` + destructive 图标风格）：图标 + 标题（i18n `errors:crash.title`）+ message（`error?.message`，等宽小字）+ 「重载应用」按钮（`() => location.reload()`）+ 「复制错误」按钮（`navigator.clipboard.writeText(error?.stack ?? error?.message ?? "")`）。
  - 用 `useTranslation("errors")`。
- 挂载：`main.tsx` → `<StrictMode><ErrorBoundary><App /></ErrorBoundary></StrictMode>`。

## 7. 全局未捕获兜底（`src/services/error/global-handlers.ts`）

```text
installGlobalErrorHandlers():
  window.addEventListener("error", (e) => { console.error(...); toast.error(t errors:uncaught) })
  window.addEventListener("unhandledrejection", (e) => { console.error(...); toast.error(t errors:uncaught) })
```

- 用 `i18n.t("errors:uncaught")`（import i18n 单例，非 hook）取文案。
- 模块底部直接 `installGlobalErrorHandlers()` 调用一次（模块副作用），`main.tsx` `import "./services/error/global-handlers"`。导出函数供测试调。
- **非致命**：只 toast + log，不切视图/不抛。渲染崩溃归 ErrorBoundary，这里管 async/全局。

## 8. i18n（扩 `errors` namespace，en + zh）

`errors.json` 顶层加：

- `crash`: `{ title, message_hint, reload, copy, copied }`
- `toast`: `{ saved, opened, imported, exported, save_failed, open_failed, import_failed, export_failed }`（带 `{{name}}`/`{{path}}` 插值的用 i18next 插值）
- `uncaught`: 全局兜底通用文案（如「发生了未预期的错误 / An unexpected error occurred」）

> 复用既有 `errors` ns → `errors.json` 已在 `i18n/types.ts` 注册，加 key 不需碰 config/types（呼应 [[i18n-typing]]）。
