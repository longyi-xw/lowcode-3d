## TL;DR

补全编辑器 5 个缺位快捷键：**Delete / Backspace**（删整子树）/ **Cmd+D**（深拷贝节点）/ **F**（聚焦相机到选中节点）/ **Space**（Play/Pause toggle）/ **Esc**（清 selection），并新增一个 shadcn `<Dialog>` 形态的快捷键帮助面板（`?` + `Cmd+/` 触发，展示全部已有 + 新增快捷键）。Delete + Cmd+D 配套两个新 Command 类（`DeleteNodeCommand` / `DuplicateNodeCommand`）+ `useSceneStore` 两个 mutator（`removeNodeSubtree` / `duplicateNode`）+ ThreeAdapter `focusOnNode(nodeId)` 新 API。一个 PR 拆 6 sub-task，约 半周-1 周。

## 1. 目标 & 非目标

### 目标

- **5 个快捷键落地**：Delete/Backspace、Cmd+D、F、Space、Esc 各自语义清晰、与现有 shortcut 模式（`use-gizmo-shortcuts.ts` / `use-keyboard-shortcuts.ts`）保持一致的守卫策略（跳过 INPUT/TEXTAREA/contenteditable、play mode 守卫）
- **DeleteNodeCommand + DuplicateNodeCommand**：所有节点编辑动作走 Command 总线，可撤销可重做（PR #7 约定）
- **`useSceneStore` 加 `removeNodeSubtree` / `duplicateNode` mutator**：保持现有 4 个 behavior mutator 的设计风格（structural sharing + identity update via `mutateNode` helper）
- **`ThreeAdapter.focusOnNode(nodeId)` 新 API**：把 OrbitControls.target 移到节点世界坐标 + 调 camera.position 距离让 bounding box fit 视口（瞬间切，不动画）
- **快捷键帮助面板**：shadcn `<Dialog>` 形态、`?` + `Cmd+/` 双触发、5 个分组（Project / Edit / Transform / Selection·View / Play / Help）、从 `shortcuts-registry.ts` 单源驱动渲染
- **i18n**：`help.*` + `shortcuts.*` namespace 的 zh-CN + en-US 翻译

### 非目标

- 不做命令面板（`Cmd+K` searchable command palette） —— 体量大，留给 v0.2+ 或后续 sub-stage
- 不做快捷键自定义（settings 面板里改键位）—— 用户可改的 settings 是 v0.2 工作
- 不做多选 + 批量 Delete/Cmd+D —— 多选系统本身 v0.2 才落地
- 不做 F 的相机平滑过渡动画 —— 瞬间切已足够（QA brainstorm 结论）
- 不做 helper / locked 节点的 Delete/Cmd+D 反向特殊化（如"先 unlock 再删"）—— 静默 no-op
- 不做 Tauri 原生 menu 的"Edit > Delete" / "Edit > Duplicate" 菜单项 —— 留给 3.5 发布流程一并整理（macOS native menu 已有 File 项，扩 Edit 项是独立工作）
- 不动 `useCommandHistoryShortcuts` / `useGizmoShortcuts` —— 它们已经各管一摊，新 hook 不合并

### 成功标准

1. 选中节点按 Delete → 节点 + 整子树消失；Cmd+Z 完全还原（含 children 顺序、behaviors、transform、user_data 全部字段）
2. 选中节点按 Cmd+D → 出现 `"{name} Copy"` 命名的新节点（深拷贝含 children + behaviors，**所有 UUID 全部新生成**），自动选中；再按 Cmd+D 出现 `"{name} Copy 2"`
3. 选中节点按 F → 相机 target 指向节点世界位置，距离自动调到节点 bounding box 完整可见
4. 任何状态按 Space → Play ↔ Edit 模式 toggle（与 PlayButton 同源 action）
5. 按 Esc → selection 清空（gizmo 消失、Outline 消失、Properties 显示空状态）；若 Radix Dialog 打开，Dialog 自带 Esc 优先关闭
6. 按 `?` 或 `Cmd+/` → 帮助面板打开，全部 14+ 条快捷键分组列出
7. 所有快捷键在 INPUT/TEXTAREA/contenteditable 内不触发
8. play mode 下 Delete/Cmd+D/Esc 不动 SceneGraph，与 command-history freeze 约定一致
9. `pnpm lint` / `pnpm typecheck` / `pnpm test` 全绿；新增测试覆盖 6 sub-task

## 4. 快捷键语义

### 4.1 总表

| Key                    | Action                                                           | 守卫条件                                                                           | 进 command-history?  |
| ---------------------- | ---------------------------------------------------------------- | ---------------------------------------------------------------------------------- | -------------------- |
| `Delete` / `Backspace` | `exec(new DeleteNodeCommand({node_id, prev_subtree}), editor)`   | INPUT 跳过；play mode 跳过；helper / `isEffectivelyLocked` 跳过；无 selection 跳过 | ✅                   |
| `Cmd+D` / `Ctrl+D`     | `exec(new DuplicateNodeCommand({node_id, new_subtree}), editor)` | 同上 + helper 拒复                                                                 | ✅                   |
| `F`                    | `adapter.focusOnNode(selectedNodeId ?? null)`                    | INPUT 跳过；无 modifier；无 selection 时聚焦 scene 中心（不报错）                  | ❌（视图状态非编辑） |
| `Space`                | `setPlayState(playState === 'play' ? 'edit' : 'play')`           | INPUT 跳过；button focused 时跳过（避免双触发）                                    | ❌                   |
| `Esc`                  | `setSelectedNodeId(null)`                                        | INPUT 跳过；Radix Dialog 打开时 Dialog 自带 Esc 优先（不需特殊处理）               | ❌                   |
| `?`                    | `setHelpOpen(true)`                                              | INPUT 跳过；无 modifier                                                            | ❌                   |
| `Cmd+/` / `Ctrl+/`     | `setHelpOpen(true)`                                              | INPUT 跳过；带 Cmd/Ctrl modifier                                                   | ❌                   |

### 4.2 共享守卫工具

新建 `src/ui/viewport/use-editor-shortcuts.ts` 顶层 helper：

```ts
function isInTextInput(e: KeyboardEvent): boolean {
  const t = e.target as HTMLElement | null;
  if (!t) return false;
  const tag = t.tagName;
  return tag === "INPUT" || tag === "TEXTAREA" || t.isContentEditable;
}
```

复用 `isEffectivelyLocked` from `src/core/scene/policy.ts`。

### 4.3 Space 与 button focus 冲突处理

PlayButton (PR #21) 被 click 后保留 focus，再按 Space 浏览器原生会触发 button click。两种处理：

1. **首选**：keydown handler 检查 `e.target.tagName === 'BUTTON'` 直接 return（让原生 Space-on-button 处理）
2. 备选：每次 PlayButton click 后 `e.currentTarget.blur()`

plan 阶段 S6 实施时择优。spec 不强制（实现细节）。

### 4.4 helper / locked 守卫复用

```ts
function canEditNode(node: SceneNode | undefined): boolean {
  return !!node && !isEffectivelyLocked(node);
}
```

Delete/Cmd+D 都先调它再 exec Command。守卫失败静默 no-op（不弹 toast——这是 hover panel 已经通过 disabled 状态告诉用户的事情）。

## 5. DeleteNodeCommand + 子树删除

### 5.1 mutator 对（删除 + 还原）

S1 一起实现两个对称 mutator：

```ts
removeNodeSubtree(nodeId: string): void;
restoreNodeSubtree(snapshot: SceneNodeSnapshot): void;
```

**`removeNodeSubtree`**：递归删除 `nodeId` + 所有后代节点，并从 `parent.children_ids` 中移除 `nodeId`。

**`restoreNodeSubtree`**：DeleteNodeCommand.revert 调用，按 snapshot 把 root + descendants 一起塞回 `nodes` map，且把 root 的 id 在 parent.children_ids 的 `snapshot.insert_index` 位置插回。`snapshot.descendants` 按"深度优先序"保存确保 children_ids 引用始终指向已存在的节点。

实现要点：

- 用 BFS/DFS 收集 `nodeId` + 所有后代 id 到 `idsToRemove: Set<string>`
- 新 `nodes` map 排除这些 id
- 父节点（`nodes[node.parent_id]` if non-null）的 `children_ids` filter 掉 `nodeId`
- `metadata.updated_at` 刷新（沿用 `mutateNode` helper 但需扩展支持多 node 同时更新——可能引入新 helper `mutateScene(s, transform)`，spec 不约束实现）
- 根节点（`parent_id === null`）按现状（v0.1 单根 group 假设——但 `parent_id: string | null` 允许多根；如果是根，从 `scene.root_node_ids` 列表里移除）
- 调用方应清 `useUIStore.selectedNodeId` 如果它在 idsToRemove 内（由 Command 调用方完成，mutator 不动 UI store）

### 5.2 `DeleteNodeCommand`

**Payload**：

```ts
interface DeleteNodePayload {
  node_id: string;
  prev_subtree: SceneNodeSnapshot; // 完整子树 + parent_id + children_ids 中的位置
}

interface SceneNodeSnapshot {
  root: SceneNode; // 被删的根 (含 parent_id + 在 parent.children_ids 中的 insert_index)
  descendants: SceneNode[]; // 全部后代节点（深度优先序）
  insert_index: number; // 在 parent.children_ids 中原来的位置（revert 时插回此位置）
}
```

**apply**：调 `store.removeNodeSubtree(node_id)` + 调用 `useUIStore.setSelectedNodeId(null)`（如果当前选中在子树内）

**revert**：调 `store.restoreNodeSubtree(prev_subtree)` —— 新增第三个 mutator，按 snapshot 顺序把 root + descendants 一起塞回 nodes map，且把 root 的 id 在 parent.children_ids 的 `insert_index` 位置插回。

**canMergeWith**：永远 false（每次 Delete 是独立编辑动作）

### 5.3 错误隔离

- `nodeId` 不存在：mutator no-op；Command 不该被 exec（守卫拦了），但即使 exec 也安全
- helper 节点：由 Command 调用方守卫；mutator 不再次检查 lock（mutator 是 pure data op）
- play mode：由 `useCommandHistoryStore.execute` 守卫拦了（PR #21）

## 6. DuplicateNodeCommand + 子树复制

### 6.1 命名算法

`generateCopyName(originalName: string, siblings: string[]): string`：

```
输入: "Cube"          siblings: ["Cube", "Light"]
      "Cube" 已在 siblings → 找空位
      "Cube Copy" 不在 → 返回 "Cube Copy"

输入: "Cube"          siblings: ["Cube", "Cube Copy", "Light"]
      "Cube Copy" 已在 → 找 "Cube Copy 2"... → 返回 "Cube Copy 2"

输入: "Cube Copy"     siblings: ["Cube Copy"]
      → 返回 "Cube Copy 2" (不是 "Cube Copy Copy")

输入: "Cube Copy 2"   siblings: ["Cube Copy 2"]
      → 返回 "Cube Copy 3"
```

正则：先匹配尾部 ` Copy( N)?` 模式（N 是正整数）。如果原名匹配，base = 去掉后缀后的部分；否则 base = 原名。然后从 N=空 开始找空位（"Copy" → "Copy 2" → "Copy 3"），返回 `${base} Copy${N || ""}`。

### 6.2 `useSceneStore.duplicateNode(nodeId)` mutator

**语义**：深拷贝 `nodeId` 子树，所有 UUID 重新生成（node.id + 每个 behavior.id），命名按 `generateCopyName` 计算，挂到原 parent 的 children_ids 末尾（**不是** 紧邻 source 的位置——简单 + 与"复制粘贴"心智一致）。

**返回**：新根节点的 id（mutator 不能返回值——Zustand `set` 不返回；新 id 由调用方在 exec 前生成，作为 Command 的 `new_subtree.root.id`）

实施方式：

1. Command 构造时先调一个 pure helper `cloneSubtreeWithNewIds(source_root_id, allNodes): SceneNodeSnapshot` 计算整个新子树（含所有新 UUID + 命名 + 重定向 parent_id / children_ids）
2. `useSceneStore.duplicateNode(nodeId, new_subtree: SceneNodeSnapshot)` 把已计算好的 snapshot 插入

**Mutator 签名**：

```ts
duplicateNode(nodeId: string, new_subtree: SceneNodeSnapshot): void;
// 不再回调；新子树 + 新 id 由 caller 通过 Command 携带
```

### 6.3 `DuplicateNodeCommand`

**Payload**：

```ts
interface DuplicateNodePayload {
  source_node_id: string;
  new_subtree: SceneNodeSnapshot; // 已计算的新子树
}
```

**apply**：`store.duplicateNode(source_node_id, new_subtree)` + `setSelectedNodeId(new_subtree.root.id)`

**revert**：`store.removeNodeSubtree(new_subtree.root.id)` + `setSelectedNodeId(source_node_id)`

**canMergeWith**：永远 false

### 6.4 behaviors 处理

复制时每个 `BehaviorBinding.id` 生成新 UUID，`behavior_type` / `enabled` / `parameters` 不变。这保证两个节点上各自可以编辑独立的 binding。

## 7. focusOnNode + ThreeAdapter API

### 7.1 新接口

```ts
// src/runtime/three/adapter.ts (private extension, not in IRuntimeAdapter)
focusOnNode(nodeId: string | null): void;
```

- `nodeId === null`：聚焦到 scene 中心（target = (0,0,0)，camera distance 默认 fit）
- 其他：拿 `getRuntimeObject(nodeId)` 的 `THREE.Object3D`，计算其世界 bounding box（`new THREE.Box3().setFromObject(obj3d)`），target = box.center，camera distance = max(box.size) × C（C 是常数，初始用 1.5）

### 7.2 ThreeViewport bridge

`ThreeViewport.tsx` 通过 `useEditorShortcuts` 调用 adapter。adapter ref 已经在 viewport 内部持有（mount effect 创建）。提供一个 export 函数 `useFocusOnNode()`（hook）或在 useUIStore 加 `focusRequestId` 事件 dispatch：

**推荐做法**：在 `useUIStore` 加 `pendingFocusNodeId: string | null | undefined` 字段（undefined = no request, null = focus scene, string = focus node id），ThreeViewport 用 selector watch 它，触发后自己清回 undefined。这样保持 React 单向数据流且测试好打。

```ts
// services/ui/store.ts
pendingFocusNodeId: string | null | undefined;
requestFocus: (nodeId: string | null) => void;  // 设值
consumeFocusRequest: () => void;                // 清回 undefined
```

`use-editor-shortcuts.ts` 收到 F 后 `requestFocus(selectedNodeId)`；ThreeViewport effect watch `pendingFocusNodeId`，非 undefined 时调 `adapter.focusOnNode` + `consumeFocusRequest`。

### 7.3 OrbitControls 集成

`focusOnNode` 内部：

1. `controls.target.copy(targetVec)`
2. 计算从 target 到当前 camera 方向的单位向量
3. `camera.position.copy(target).add(dir.multiplyScalar(distance))`
4. `controls.update()`

不动 `controls.minDistance` / `maxDistance`（避免越界），让 OrbitControls 自然处理。

## 9. use-editor-shortcuts hook + EditorView 集成

### 9.1 `src/ui/viewport/use-editor-shortcuts.ts`

模式沿用 `use-gizmo-shortcuts.ts` / `use-keyboard-shortcuts.ts`：

```ts
import { useEffect } from "react";
import { isEffectivelyLocked } from "@/core/scene/policy";
import { useCommandHistoryStore } from "@/services/command-history/store";
import { getSceneEditorStore, useSceneStore } from "@/services/scene/store";
import { useUIStore } from "@/services/ui/store";
import { DeleteNodeCommand } from "@/core/command/commands/delete-node";
import { DuplicateNodeCommand } from "@/core/command/commands/duplicate-node";
// + helpers

export function useEditorShortcuts(): void {
  useEffect(() => {
    const onKeyDown = (e: KeyboardEvent) => {
      if (isInTextInput(e)) return;
      // ... per-key handlers
    };
    window.addEventListener("keydown", onKeyDown);
    return () => window.removeEventListener("keydown", onKeyDown);
  }, []);
}
```

**每个 key 的逻辑**（伪代码骨架）：

```
key = e.key
isMod = e.metaKey || e.ctrlKey

if (key === "Delete" || key === "Backspace") {
  guard play mode + selection + canEdit
  exec(new DeleteNodeCommand({ node_id, prev_subtree: snapshot(node) }))
  preventDefault
}
else if (isMod && key.toLowerCase() === "d") {
  same guards
  exec(new DuplicateNodeCommand({ source_node_id, new_subtree: cloneWithNewIds(node) }))
  preventDefault
}
else if (key.toLowerCase() === "f" && !isMod) {
  requestFocus(selectedNodeId)  // null 也合法
  preventDefault
}
else if (key === " " && !isMod) {
  if (e.target instanceof HTMLButtonElement) return  // §4.3
  setPlayState(playState === "play" ? "edit" : "play")
  preventDefault
}
else if (key === "Escape" && !isMod) {
  setSelectedNodeId(null)
  // Don't preventDefault — let Radix Dialog also see it
}
else if (key === "?" && !isMod) {
  setHelpOpen(true)
  preventDefault
}
else if (isMod && key === "/") {
  setHelpOpen(true)
  preventDefault
}
```

## Open questions for plan stage

写 plan 时需进一步决议：

1. **`focusOnNode` 的 distance 算法**：是 `max(box.size) × 1.5` 还是 `box.size.length() × 1.5`？前者更保守、后者更紧密。建议 plan 阶段用 `Math.max(box.size.x, box.size.y, box.size.z) * 2`（留余地），实测视觉验证调整。
2. **Space 与 button focus 冲突**：用 `e.target.tagName === 'BUTTON' return` 还是改 PlayButton click 后 blur？前者侵入少（在 hook 内统一处理），建议用前者。
3. **`?` 键在中文 IME 下**：macOS 拼音输入法可能拦截 shift+/。plan 阶段做 manual smoke 验证；若失效，加 `Cmd+/` 作为备份触发（spec 已经加了），不在 spec 强制处理 IME。
4. **`Cmd+D` 与浏览器原生"加书签"**：Tauri 内不会触发，但 `pnpm dev` 走 Vite browser 时会。生产 `pnpm tauri dev` 是真实环境；plan 阶段 visual verification 必须用 `pnpm tauri dev`，不能仅在 browser 跑。
5. **`generateCopyName` 的兄弟节点范围**：是 source 节点的 parent 的 children_ids（按 `nodes[child_id].name`）还是全 scene 所有节点的 name 集合？建议 plan 阶段用 **parent.children 范围**（"Copy 2" 是相对兄弟的，不是全场景），与 Figma / Sketch 行为一致。
6. **`SceneNodeSnapshot` 的命名 + 落地位置**：是放 `src/core/scene/snapshot.ts` 还是 `src/core/command/commands/_snapshot.ts`？建议前者（与 scene types 同源），方便 future restore / 序列化复用。
