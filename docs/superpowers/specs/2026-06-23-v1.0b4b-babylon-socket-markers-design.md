# v1.0 B4b — Babylon socket markers 设计

**目标：** 让 Babylon 模式选中/编辑时显示 socket 插槽标记（对齐 Three），并借此完成 B3a 计划的「B4 抽」——把 socket markers 从 `ThreeViewport` 组件层提升为引擎中立的 `IRenderHost` 自有 overlay。

**架构：** socket markers 成为 host 自有的「选中态 overlay」，与 outline/gizmo 并列。两个 host 各自渲染，数据源**复用** `setSnapProvider` 已提供的 `{id, sockets, visible, type}` + `setSelection` 已存的当前选中。组件退化为只在「场景变 / 选中变」时调一次 `host.syncSocketMarkers()`；拖拽期由 host 内部自重建。

**技术栈：** Three.js 0.184（`THREE.Group` + `SphereGeometry` + `MeshBasicMaterial`，已存在）/ Babylon `@babylonjs/core` 9.11（`TransformNode` + `MeshBuilder.CreateSphere` + `StandardMaterial`）；Vitest + NullEngine headless。

---

## 背景

B3b 在两引擎都实现了 socket **吸附**（`core/snap/sockets.ts` + 两侧 `snap-features.ts` 的 `socketPoints`），但 socket **视觉标记**至今只在 `ThreeViewport.tsx` 组件层（v0.4 C 遗留），Babylon 一片空白——用户验收为「能吸看不见」，明确留到 B4。B3a 抽 `ThreeRenderHost` 时把 socket markers「最小抽取留壳（B4 抽）」，本设计即兑现该收敛。

现状关键事实（已核实）：

- `onGizmoChange` 只在 `src/runtime/three/render-host.ts:259`，是 **Three 专属面**，不在 `IRenderHost` 契约里，Babylon host 也没有。它存在的唯一目的就是让组件在 host 拥有的拖拽帧里重建 markers。
- `IRenderHost` 契约现有：`mount/start/stop/resize`、`setSelection`、`setGizmoMode`、`setGizmoTarget`、`onTransformCommit`、`setSnapProvider`、`dispose`。无任何 marker 方法。
- Three 的 `rebuildSocketMarkers`（`ThreeViewport.tsx`）：独立 overlay `Group`（不入节点层级），共享 geo + 两材质（cyan `#22d3ee` 未选 / amber `#f59e0b` 选中），遍历**所有带 socket 的节点**，每 socket 一球，位置 = `socket.position` × 节点 `matrixWorld`，`raycast` 置空（pickAt 永不命中）。重建时机：选中变 / 场景变 / 拖拽帧（`onGizmoChange`）/ 初始。

## 触发接缝决策

host 拥有「怎么渲染」，组件拥有「场景何时变」（diff→`adapter.syncNode` 在组件侧，host 无从观察场景图编辑）。故 host 需要一个「场景变了，重建 markers」的外部信号。

**采用方案：契约加单个 `syncSocketMarkers()`，host 内部在拖拽帧自重建。**

- 组件在 init / `applyDiff` 后 / 选中变 三处调用 `host.syncSocketMarkers()`。
- 拖拽期由 host 自己的 gizmo 拖拽回调内部重建 → **删除 `onGizmoChange`**。
- 净效果：契约 **+1 方法、−1 Three 专属方法**，拖拽接缝消失，Babylon 对等白捡。

否决的替代：① host 每渲染帧自重建（每帧网格 churn、偏离事件驱动，YAGNI）；② 仅折进 `setSelection`（漏掉「选中不变但场景/socket 编辑」的重建）。

## 契约变更（`src/runtime/render-host.ts`）

```ts
interface IRenderHost {
  // …现有…
  /** 按当前 snap provider 的 socket 数据 + 当前选中重建 socket-marker overlay。 */
  syncSocketMarkers(): void;
}
```

`ThreeRenderHost.onGizmoChange` 删除（含其字段与调用点）。

## 新中立模块 `src/runtime/socket-markers.ts`

共享视觉常量，锁定两引擎逐像素一致（各 host 自行把 hex 转引擎色）：

```ts
export const SOCKET_MARKER = {
  radius: 0.06,
  color: "#22d3ee", // 未选中
  colorSelected: "#f59e0b", // 选中节点的 socket
} as const;
```

世界坐标计算不入此模块（Three `Matrix4` 与 Babylon `Matrix` 类型不同），各 host 用本引擎矩阵 API 算 `socket.position × nodeWorldMatrix`。

## Three 迁移（行为保持，零视觉变化）

- `ThreeViewport.tsx`：删除整段 socket-marker（`socketGeo/socketMat/socketMatSel/noRaycast/socketMarkers` group、`rebuildSocketMarkers`、cleanup 的 dispose、`host.onGizmoChange(rebuildSocketMarkers)` 接线）。三处 `rebuildSocketMarkers()` 调用点改为 `host.syncSocketMarkers()`（含 `syncSelectionShell` 内、场景订阅内、初始）。
- `ThreeRenderHost`：原样接收上述逻辑——私有 `rebuildSocketMarkers()`（构建/清理 overlay group，用 `SOCKET_MARKER` 常量）+ 公开 `syncSocketMarkers()` 调它；gizmo 的 `objectChange`（host 已拥有）内部调私有重建以替代 `onGizmoChange`。overlay 在 `mount` 建、`dispose` 清。
- 材质颜色改用 `SOCKET_MARKER.color/colorSelected`（`new THREE.Color(hex)`），半径用 `SOCKET_MARKER.radius`。值与现状一致 → 视觉不变。

## Babylon 实现（`src/runtime/babylon/render-host.ts`）

- overlay：`TransformNode("socketMarkers", scene)`，`mount` 建、`dispose` 清。
- 两个共享 `StandardMaterial`：`disableLighting = true` + `emissiveColor = Color3.FromHexString(SOCKET_MARKER.color / .colorSelected)`（对齐 Three `MeshBasicMaterial` 的 unlit 观感）。
- 私有 `rebuildSocketMarkers()`：dispose overlay 现有子网格 → 遍历 snap provider 节点，每 socket `MeshBuilder.CreateSphere({ diameter: radius*2 })`，parent = overlay，`isPickable = false`，position = `Vector3.TransformCoordinates(socketLocal, node.getWorldMatrix())`，material = 选中节点用 amber 否则 cyan。
- 公开 `syncSocketMarkers()` 调私有重建。host 现有 `onGizmoDrag`（B3b/B4c 拖拽+吸附处）末尾调私有重建，使拖拽时 markers 跟随。
- `BabylonViewport.tsx`：在 init（首个 `applyDiff` 后）/ 每次 `applyDiff` 后 / 选中变（UI 订阅内，紧随 `setSelection`）调 `host.syncSocketMarkers()`，与 Three 三处对称。

## 数据流

```
选中变 / 场景变 → 组件 host.syncSocketMarkers()
                  → host 读 snapProvider() 的 socket 数据 + 已存选中 + adapter.getRuntimeObject(id) 世界矩阵
                  → 重建 overlay（选中节点 socket amber，其余 cyan）
拖拽帧 → host 内部 gizmo 回调 → 私有 rebuildSocketMarkers（markers 跟随被拖节点）
pickAt → marker 非拾取（Three raycast 置空 / Babylon isPickable=false）→ 永不选中 marker
```

## 测试

- `socket-markers.ts` 常量单测：值锁定（radius/color/colorSelected）。
- `ThreeRenderHost`（迁移现有 Three marker 断言，保持绿）：`syncSocketMarkers` 后 overlay group 子节点数 = 全场景 socket 总数；选中节点的 marker 用 selected 材质；拖拽（objectChange）触发重建；`dispose` 清 overlay。
- `BabylonRenderHost`（NullEngine）：`syncSocketMarkers` 后 `socketMarkers` TransformNode 子节点数正确；marker 世界坐标 ≈ `socket × nodeWorldMatrix`；选中节点 socket 用 amber 材质引用；marker `isPickable === false`；`pickAt` 命中 marker 区域返回 null（或不返回 marker）；`dispose` 清 overlay。

## 非目标（YAGNI）

- 不改 marker 可见性策略：仍「所有带 socket 节点显示、选中 amber」（= Three 现状）。
- play 模式下 marker 行为保持 Three 现状不变（不新增隐藏逻辑）。
- marker 纯视觉，不做拾取/交互/编辑。
- 不做 marker 池化/位置增量更新；拖拽期沿用 Three 的「整重建」，若 smoke 见卡顿再单独优化。
