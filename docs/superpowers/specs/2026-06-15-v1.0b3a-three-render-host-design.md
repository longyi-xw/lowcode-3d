# v1.0 sub-stage B3a — 抽取 ThreeRenderHost（行为保持重构）设计

日期：2026-06-15
分支：`feat/v1.0b3a-three-render-host`
前置：B2（PR #40，拾取 + 选中描边跨引擎）

---

## 1. 背景与目标

B1/B2 走「Babylon 先行、ThreeViewport 零改动并行」：`IRenderHost` 只有 Babylon 一个实现，Three 的 render loop / 相机 / 拾取 / 描边 / gizmo / snap 仍全部内联在 791 行的 `ThreeViewport.tsx` 里。B2 注释已记：「gizmo 不动，B3 抽 ThreeRenderHost 时一起收」。

**B3 = gizmo + snap 跨引擎**，体量大且含两类工作：①把 Three 的 render host 抽出来（重构），②给 Babylon 加 gizmo+snap（新功能）。已与用户确认拆成两个 PR：

- **B3a（本 spec）**：抽 `ThreeRenderHost implements IRenderHost`，借成熟的 Three 实现**定义 IRenderHost 的 gizmo+snap 契约**。纯重构，零用户可见变化。
- **B3b（后续 spec）**：`BabylonRenderHost` 实现同一契约（gizmo 用 Babylon `GizmoManager`，snap 写 Babylon 特征提取）。

**B3a 目标**：把 render loop / camera / resize / pick / outline / gizmo / snap 从 `ThreeViewport` 抽进 `ThreeRenderHost`；`ThreeViewport` 退化为薄 React 壳；Three 编辑行为逐项等价。

### 已与用户确认的决策

- **拆分时序 = 先抽 Three 再做 Babylon（方案 A）**。理由：gizmo 是复杂交互契约（mode 切换 / 拖拽生命周期 / 拖拽中吸附 / release 提交 command / lock 感知 / play detach），且**成熟参考已存在于 Three**——用成熟实现把契约「形式化」，再让第二引擎验证它，比 B1/B2 的「Babylon 先行发现」更稳；同时把最大的债（791 行单体）单独还掉，重构与新功能风险隔离。已否决：并行（Three 不动，契约会漂移、两引擎代码结构不对称）、big-bang（一个 PR 抽+加，脆弱的 Three 拖拽/竞态代码与新 Babylon 代码混在一起，回退风险高）。
- **抽取边界 = 最小抽取**。只抽 IRenderHost 当前 + B3 覆盖的：render loop / camera / resize / pick / outline / gizmo / snap（含 OBB 特征提取 helper）。socket markers / asset drop / play-pause / focus **留在 ThreeViewport**，B4 与其 Babylon 对应物一起抽——它们的跨引擎契约尚未设计，现在抽 = 提前设计未验证的契约（YAGNI 风险）。
- **gizmo 契约 = store/command 无关解耦**：host emit `onTransformCommit` 回调，viewport 接 `executeCommand`；host 不 import 任何 Zustand store。
- **留守 B4 代码的依赖 = 引擎专有面**：focus / socket markers / asset drop 通过 `ThreeRenderHost` 的非 IRenderHost getter/方法（`adapter`、`focusCamera`）访问，镜像 `BabylonRenderHost.adapter`/`selectionLayer` 既有模式，不污染 IRenderHost。

## 3. IRenderHost 契约扩展

在 `src/runtime/render-host.ts` 的 `IRenderHost` 上增加 gizmo + snap，保持 store/command 无关：

```ts
type Vec3 = [number, number, number];

/** 宿主拖拽起手时拉取的、做 snap 目标缓存所需的最小场景信息（store 无关）。 */
interface SnapNode {
  id: string;
  sockets: readonly Socket[];
  visible: boolean;
  type: SceneNode["type"]; // 用于排除 helper
}

interface IRenderHost {
  // …已有：engine / mount / start / stop / resize / setSelection / dispose
  setGizmoMode(mode: GizmoMode): void;
  /** attach gizmo 到节点；null = detach。locked → 只描边不 attach。 */
  setGizmoTarget(node_id: string | null, locked: boolean): void;
  /** 注册一次：宿主在每次完成的拖拽（mouseUp 且 transform 变化）调用它。 */
  onTransformCommit(
    cb: (node_id: string, prev: Transform, next: Transform) => void,
  ): void;
  /** 注入场景快照 provider：宿主在拖拽起手缓存 snap 目标时拉取（不 import store）。 */
  setSnapProvider(provider: () => SnapNode[]): void;
}
```

**宿主自管的拖拽/吸附机制**（从 ThreeViewport 逐字搬入 ThreeRenderHost）：

- gizmo attach / detach / setMode；`dragging-changed` 时禁用 orbit + 拖拽中清描边、release 时从当前 selection 恢复描边。
- pointer 修饰键追踪（capture 阶段 `pointermove`/`pointerdown` 读 `ctrlKey||metaKey`，不用 keydown/keyup——既有教训）。
- `mouseDown`：capture 起始 transform + 经 `setSnapProvider()` 拉场景、缓存其它节点的 bbox 特征 + socket 点（屏幕坐标，整段手势内相机冻结故有效）。
- `objectChange`：`snapDraggedObject` 优先级链 socket → node（仅无 socket 节点）→ grid，仅 translate 模式 + 修饰键按下时生效。
- `mouseUp`：transform 变化则 `onTransformCommit(id, prev, next)`。

**类型归属**：

- `GizmoMode = "translate"|"rotate"|"scale"` 当前在 `src/services/ui/store.ts`。分层为 `core ← runtime ← services ← ui`，`services/ui/store` 与 `runtime/render-host` 都能引的最低层是 `core`；且 GizmoMode 是编辑器交互类型（非序列化场景数据），不放 `scene/types.ts`。定为新文件 `src/core/editor-types.ts`，两处都从那里 import。
- `Transform` / `Socket` / `SceneNode` 已在 `core/scene/types`，IRenderHost 可直接 import（已有 `RuntimeTarget` 先例）。

## 4. ThreeRenderHost 引擎专有面

镜像 `BabylonRenderHost.adapter` / `selectionLayer` 既有模式，暴露**非 IRenderHost** 的 Three 专有面给留守的 B4 代码：

- `get adapter(): ThreeAdapter` — socket markers（`adapter.scene.add` / `getRuntimeObject`）、asset drop（`raycastGroundPoint`）用。
- `focusCamera(target: Vec3, distance: number): void` — focus effect 用（相机 + OrbitControls 已搬进 host）。

IRenderHost 保持干净；这些面随 B4 把对应功能抽进 render host 时再决定是否升格为跨引擎契约。

## 6. ThreeViewport 抽取后（薄壳）

mount effect 内：

1. 建 `ThreeRenderHost` → `mount(canvas)` → seed → `start()`。
2. `onTransformCommit((id, prev, next) => executeCommand(new SetNodeTransformCommand({node_id:id, transform:next, prev_transform:prev})))`。
3. `setSnapProvider(() => …)` 从 `useSceneStore` 读当前节点 → `SnapNode[]`。
4. 订阅 `useUIStore`：selectedNodeId 变 → `host.setGizmoTarget(id, isEffectivelyLocked(node))` + `host.setSelection(id)`；gizmoMode 变 → `host.setGizmoMode`；playState 变 → enter/exitPlay（留守）。
5. 订阅 `useSceneStore` → diff → `adapter.syncNode`（经 host.adapter）+ 重建 socket markers。
6. click-pick → `setSelectedNodeId(adapter.pickAt(...))`（click-vs-drag guard 逐字保留）。
7. **保留**（用 host 专有面）：socket markers overlay、asset drop（`raycastGroundPoint` + `AddNodeCommand`）、play/pause（behavior install/tick/uninstall + transform 快照 + 进入时 `host.setGizmoTarget(null)`/`host.setSelection(null)`、退出时恢复）、focus effect（调 `host.focusCamera`）。
8. **seedScene 竞态重放**：`seeded.then` 后重放 selection（`host.setGizmoTarget`+`setSelection`）+ socket markers，`unmounted` 守卫——既有竞态修复，现在跨 host/壳两边，须原样保留。

> 结构上 ThreeViewport 向 BabylonViewport 靠拢（建 host → mount → 订阅 → dispose），但因留守 B4 功能，仍比 BabylonViewport 厚。完全对称留待 B4。

## 8. 风险

- **seedScene 竞态重放跨 host/壳**——最易回退点。selection（gizmo+outline，已搬 host）与 socket markers（留壳）的重放现在分属两边，`seeded.then` 须同时驱动两者，`unmounted` 守卫不能漏。
- **拖拽 vs click guard、snap 修饰键 pointer 追踪**——逐字搬，别「顺手优化」（既有教训：keydown/keyup 追踪修饰键会卡死）。
- **dispose 所有权**：adapter 拥有 scene；host.dispose 调 adapter.dispose（镜像 Babylon 规则）。socket markers 的 geo/material dispose 留壳，须在壳 cleanup 里、host.dispose 之前/之后顺序正确。
- **类型搬迁**：`GizmoMode` 挪位要同步改 `services/ui/store` 及所有 import 点（typecheck 兜底）。
