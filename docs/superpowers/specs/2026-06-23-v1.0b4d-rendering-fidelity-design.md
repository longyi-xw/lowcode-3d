# v1.0 B4d — Babylon 渲染观感对齐 Three + 双引擎 IBL 设计

**目标：** 消除 Babylon 与 Three 的渲染观感分歧（底色 sRGB、光强），并给两引擎一致地补上中性 IBL（让金属更好看），使引擎切换观感无缝；顺带收尾 B4b 遗留的 Babylon rotate/scale 拖拽 socket-marker 实时跟随。

**架构：** 四块独立改动，各自落在对应 host/adapter：① Babylon 整帧 image-processing 做 sRGB 输出，对齐 Three 的 `OutputPass`；② Babylon `createLight` 施引擎光强缩放常量（smoke 标定）；③ Three 用内置 `RoomEnvironment`（程序化、无资产）+ Babylon 用 bundle 的中性 `.env`，各自设为 `scene.environment(Texture)`；④ Babylon `wireActiveGizmo` 给 rotate/scale gizmo 接 `onDragObservable` → `rebuildSocketMarkers`。

**技术栈：** Three.js 0.184（`OutputPass`、`RoomEnvironment`、`PMREMGenerator`）/ Babylon `@babylonjs/core` 9.11（`ImageProcessingConfiguration` / 整帧 post-process、`CubeTexture` `.env`、`GizmoManager`）；Vitest + NullEngine（接缝/ marker 单测）；`pnpm tauri dev` 视觉 smoke（保真度）。

---

## 背景（探索勘误）

- **IBL 现在两引擎都没有**：全仓无 `environmentTexture` / `RoomEnvironment` / HDR。所以「金属偏暗」是**两边都缺 IBL**，不是 Three↔Babylon 分歧。记忆里把「金属无 IBL」记为 Babylon gap 需修正为「两引擎都缺，B4d 一致补」。
- **真正的引擎间分歧两条**：① Three 走 composer 的 `OutputPass`（linear→sRGB，把 `0x101418` 底色提亮），Babylon `scene.clearColor` 写**原始值**、无 image processing → 底色偏暗；② **Babylon 根本没应用节点的 `intensity`/`color`**（`createLight` 只默认构造、`syncNode` 只应用 transform → 灯一律默认白色 + intensity=1），Three 的 `node-builders/light.ts` 则 `object.color.set(data.color); object.intensity = data.intensity`（create+update 都应用）。这是 pre-existing gap，是「Babylon 灯不对/偏亮」的真因——**不是缩放系数问题**。
- Three 渲染管线：`RenderPass → OutlinePass → OutputPass`；**未设** `renderer.toneMapping`（默认 `NoToneMapping`，仅 sRGB 编码）、未设显式 colorSpace（r152+ 默认 sRGB）。`renderer.setClearColor(0x101418)`。
- 两引擎的光都来自**场景节点**（默认模板 `services/scene/templates.ts` 含一个 directional light），host 不加默认光。
- Babylon 现状：`scene.clearColor = CLEAR_COLOR`（原始 `0x101418`）、PBR 材质（`babylon/material.ts`）、`createLight`（`babylon/adapter.ts`）从节点建灯，无 image processing、无 IBL。

## 范围

四块。①②③ 是渲染保真（同一子系统，一起做）；④ 是 B4b 收尾（独立的小 gizmo 修复，按用户分组并入 B4d 作为独立任务）。

---

## 1. sRGB 输出对齐（分歧①）

**问题：** Three `OutputPass` 对**整帧**（含 clearColor 背景）做 linear→sRGB；Babylon clearColor 写原始 → 背景偏暗。

**方案：** Babylon 启用**整帧 image-processing post-process**（`scene.imageProcessingConfiguration` + 让其 `applyByPostProcess` 覆盖全帧，或 `DefaultRenderingPipeline`），使背景 + 材质统一经 sRGB 输出，对齐 Three `OutputPass`。`clearColor` 仍设 `0x101418`，经 sRGB 后与 Three 一致提亮。

**⚠️ API 风险（实现期 node 实验先验）：** Babylon PBR 材质默认带 per-material image processing；若再叠整帧 post-process 可能**双重 sRGB 编码**。node 实验确认正确接法（典型：开 `applyByPostProcess` 让 IP 只在 post-process 阶段一次性施加，材质不再各自施加），避免双重编码。

**落点：** `src/runtime/babylon/render-host.ts` mount。

## 2. 光强 + 颜色对齐（修正：Babylon 根本没应用灯光属性）

**问题（勘误）：** 见背景②——Babylon 灯不应用节点 `intensity`/`color`，一律默认。真因是**属性没应用**，不是缩放不同。

**方案：** 新增 `applyLightData(light, data)`：按灯种设 `diffuse = Color3.FromHexString(data.color)` + `intensity = data.intensity * BABYLON_LIGHT_SCALE`（HemisphericLight 同样设 `diffuse`+`intensity`）。在 `createLight`（add）与 `syncNode` 的 update 分支（light 节点）两处调用，镜像 Three 的 create+update 应用。`BABYLON_LIGHT_SCALE`（Babylon 本地常量，**初值 1.0**）是 smoke 标定的**可选**亮度修正——应用真值后若两引擎在同 intensity 下仍有亮度差（PBR vs 物理光单位）再调，否则保持 1.0。须在 sRGB（第 1 块）+ IBL（第 3 块）落地**之后**于 smoke 标定（二者都改感知亮度）。不改节点数据、不动 Three。

**落点：** `src/runtime/babylon/adapter.ts`（`applyLightData` + `BABYLON_LIGHT_SCALE` 常量 + `createLight`/update 两处调用）。

## 3. 双引擎中性 IBL

让金属在两引擎都有环境可反射、更好看，且观感相近。

- **Three：** 内置 `RoomEnvironment`（程序化中性室内）经 `PMREMGenerator.fromScene()` 生成 env map → `adapter.scene.environment`。**无需资产文件**。落点 `src/runtime/three/render-host.ts` mount（生成后 dispose PMREM 临时资源）。
- **Babylon：** bundle 一个小型中性 studio `.env`（Babylon 优化 IBL 格式，~100–300KB）→ `CubeTexture` → `scene.environmentTexture`。资产置于 `src/assets/env/neutral.env`，用 Vite `?url` 导入得运行时 URL（Tauri 打包随前端）。落点 `src/runtime/babylon/render-host.ts` mount。
  - **资产获取（前置，控制者执行）：** 子代理无法可靠下载二进制 → 由控制者 `curl` 一个已知中性 studio `.env`（如 Babylon 官方 `https://assets.babylonjs.com/environments/environmentSpecular.env`）落到 `src/assets/env/neutral.env`，实现子代理只负责接线。若用户对具体 IBL 有偏好可替换。

**⚠️ 明确预期：** 两引擎 IBL **不像素级一致**（来源/卷积不同）；目标是「两边都中性、金属都变好看、观感相近」。**非目标**：像素级一致、可见 skybox 背景（只 IBL 影响材质，底色仍纯色）。

## 4. marker rotate/scale 跟随（B4b 收尾）

**问题：** Babylon `onGizmoDrag` 仅 translate 触发重建，rotate/scale 拖拽期 marker 不实时跟随（松手经 store 自愈归位）；Three 靠 `objectChange` 全模式跟随。

**方案：** `wireActiveGizmo` 里给 rotate/scale gizmo 也接 `onDragObservable.add(() => this.rebuildSocketMarkers())`（translate 路径已有）。保持 WeakSet 幂等接线（B3b 模式）。

**⚠️ API 风险（node 实验先验）：** 确认 `RotationGizmo` / `ScaleGizmo`（或其 `gizmos.rotationGizmo`/`scaleGizmo`）暴露 `onDragObservable`；若顶层无、则接各 axis 子 gizmo 的 onDrag。

**落点：** `src/runtime/babylon/render-host.ts` `wireActiveGizmo`。

## 数据流 / 落点汇总

- `babylon/render-host.ts` mount：① image-processing post-process；③ `.env` → `environmentTexture`；mount/dispose 清理 env 纹理 + post-process。
- `babylon/render-host.ts` `wireActiveGizmo`：④ rotate/scale onDrag 重建 marker。
- `babylon/adapter.ts` `createLight`：② intensity 施 `BABYLON_LIGHT_SCALE`。
- `three/render-host.ts` mount：③ `RoomEnvironment` + PMREM → `scene.environment`，dispose 清理。
- 新资产：`src/assets/env/neutral.env`。

## 测试策略（非对称，依现实）

- **视觉保真不可单测** → `pnpm tauri dev` 两引擎并排 smoke（强制，用户执行）：底色提亮一致、光强一致、金属有环境反射且两边相近、Three 无回归。
- **可 NullEngine 单测（Babylon host/adapter）：** image-processing 已启用（`scene.imageProcessingConfiguration.isEnabled` / post-process 存在）；`applyLightData` 应用 intensity+color（节点 intensity 1.5 / color #ff0000 → `light.intensity === 1.5 * BABYLON_LIGHT_SCALE`、`light.diffuse` ≈ red）；marker rotate/scale 跟随（mount + 选中带 socket 节点 + setGizmoMode("rotate") + notify rotation gizmo `onDragObservable` → `socketMarkersForTest` 重建）。
- **待 node 实验定的可测性：** Babylon `.env` 在 NullEngine 是否能令 `environmentTexture` 非空（headless 无 GPU 上传）——能则加断言，否则归 smoke。
- **Three IBL 不可单测**（`PMREMGenerator`/`RoomEnvironment` 需 WebGL，jsdom 无）→ smoke only（同 B4b 的 ThreeRenderHost 策略）。
- **planning-phase node 实验**（一次性 vitest，验完删，B3b/B4b 沿用）先验三个 API 风险：① 整帧 image-processing 与 PBR per-material IP 是否双重编码；② `.env`/`CubeTexture` 在 NullEngine 行为；③ `RotationGizmo`/`ScaleGizmo` `onDragObservable` 是否存在。

## 非目标（YAGNI）

- 不追 IBL 像素级一致（两边中性即可）。
- 不加可见 skybox / 环境背景（只 IBL 影响材质，底色仍纯色）。
- 不做阴影 / AO / bloom 等后处理特效扩展（仅对齐现有观感）。
- 光强缩放是经验标定常量，不做物理精确单位换算。
- 不改引擎中立节点数据（intensity 真值不变，只在 Babylon 侧缩放）。
